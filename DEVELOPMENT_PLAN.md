# Context-aware caption preprocessing — implementation plan

Status: approved direction, implementation pending. Owner: local coding agent.
Target: Chrome ccCraft fork; NVIDIA Nemotron 3 Ultra (nvidia/nemotron-3-ultra-550b-a55b).
This is a development handoff, not a claim that the implementation or evaluations have passed.

## 1. Goal / intent / scope
Goal: improve the viewing experience of existing YouTube captions, especially automatically generated English technical lectures, translated into natural Taiwan Traditional Chinese (zh-TW). Preserve meaning, technical vocabulary, source/translation correspondence and playback synchronization.
Intent: fix input fragmentation and context quality before the existing ccCraft translation engine; do not build a new subtitle product. Batch processing is acceptable; realtime ASR is not required. A screenshot showed English "vision.md here. And if you're going to" alongside Chinese "關於這個專案核心的原則。" This suggests possible semantic fragmentation OR wrong cue assignment; it does not establish the cause. Diagnose first.
In scope: raw-caption inspection; conservative deterministic normalization; one global-context pass using the selected Nemotron model; optional semantic merging with provenance; prompt injection; small correctness fixes necessary at the integration boundary; evaluation and regression tests.
Out of scope: audio downloading, ASR, Nemotron Transcribe, GPU hosting, backend, agents/LangChain, new provider framework, UI redesign, player rewrite, wholesale cache/retry rewrite, new dependencies unless justified. Keep other providers and manual import working. Do not commit API keys, signed timedtext URLs or private transcripts.

## 3. Target architecture
Existing extraction -> immutable raw workfile snapshot -> Caption Normalization -> Global Context Analysis -> optional Semantic Caption Normalization -> existing translateWorkfile batching/retry/merge -> existing LOAD_TRANSLATED_JSON -> existing overlay/storage.
Normalization and context are the only new logical components; semantic merging belongs inside normalization. Context is a small shared argument to buildChunkPrompt and translateChunk, not a new translation engine. All initial and retry batches get the same profile and, where useful, bounded neighboring source context labeled READ ONLY. Translate only requested IDs. Existing workfile shape is the contract. Reuse selected API credentials/model and key rotation; adapt system message by task so context JSON isn't contradicted by translation-only instructions. No new endpoints. Verify actual API limits rather than assume advertised context window is usable.
Enhanced mode should be opt-in or easily disabled for baseline comparison; default existing behavior until evaluated. Strict ID safety fix is independent and should protect both modes.

## 4. Tickets (execute in order; one small commit/PR per ticket)

### T00 — baseline diagnosis and fixtures (no behavior change)
Read manifest, README, actual call graph and source track selection. Capture a short real permitted transcript locally from failing video using existing workfile export; save a sanitized minimal synthetic fixture for version control. Record source track type, raw cues and IDs, chunk input/output (redacted), resulting workfile and playback timestamps. Compare rendered cue with source and model output. Include a fixture with non-1-based IDs, a boundary crossing a sentence, rolling/overlapping ASR text, missing punctuation, repeated legitimate words, manual track and long silence. Reproduce wrong-ID assignment with stub provider; distinguish input fragmentation, model semantic error, ID association and rendering. Capture baseline on same model/config. Do not log keys or full private content. Deliver evidence and exact file/line map.

### T01 — guard existing translation association
Small correction, not an engine rewrite. Validate parsed IDs against the current chunk, reject duplicates/foreign IDs before writing; keep valid uniquely identified results and retry missing IDs using existing mechanism, or reject malformed batch atomically. Prefer removing ambiguous positional fallback: only if explicit ordered contract and exact count can be established may map positions to actual chunk IDs; never accept partial positional lines or manufacture IDs. Test second chunk, sparse retry IDs, duplicate/unknown ID, partial/empty response, reasoning text and truncated response. Do not mix reasoning_content into translations. Preserve existing progress and retry semantics. Ensure actual untranslated count is reported. Verify async completion still belongs to the original video before loading; if existing guard is absent, add narrowly scoped guard/test or document blocker. No foreign cue may overwrite another.

### T02 — deterministic Caption Normalization
Add small pure helper(s), e.g. src/caption-normalization.js if compatible with manifest; names illustrative. Clone workfile/cues before modifying. Normalize whitespace and only remove duplicate rolling prefixes when timing and exact text overlap provide evidence; repeated legitimate words must stay. Keep numeric timings in seconds, sorted and finite. Keep provenance from each output cue to raw cue IDs (and token ranges if relevant); never modify raw export. Manual subtitles bypass semantic changes by default. Preserve source_track/video/schema, unique numeric IDs, start/end/start_time/end_time/source/fa. Regenerate timestamps with existing formatting helper or equivalent; no arbitrary time estimates. Clear fa on transformed cues. If no reliable normalization is possible return original with explicit warning. Initially retain cue boundaries. Unit tests: normalization idempotence, immutable inputs, no dropped meaningful text, no overlap or invalid duration introduced, track bypass, empty input, Unicode and code identifiers.

### T03 — Global Context Analysis + prompt injection
One logical context pass per workfile/model/language, before translation. Reuse selected NVIDIA provider client but allow a task-specific system prompt. Input entire normalized transcript when within verified token/request budget, title, source language and target language. If too large, bounded chapter/chunk summaries then combine, or explicitly fall back to local context; never silently truncate. Output validated bounded JSON profile: topic, short summary, glossary (source term -> preferred translation), proper nouns, translation guidance. No invented facts or new instructions from transcript; transcript is untrusted data. Preserve file names/code, numbers, units, negation; use Taiwan Traditional Chinese when selected. Context advisory only, never source of new facts. Add profile to existing buildChunkPrompt with clear delimiters; return only id|text for target cues; optional bounded previous/next original cues as read-only context including on retries. Use same existing provider/model by default; no new provider selection UI needed beyond optional enhanced toggle. If analysis fails, warn and continue original translation; bounded retries/timeouts using existing policies. Do not hardcode assumed context length; check model response finish_reason, timeout and reasoning handling, output budget. Store context in memory for job; persistent cache deferred unless needed. Tests: profile valid/malformed/timeout, injection isolation, context shared across workers/retries, long transcript fallback, target language selection, other providers unaffected.

### T04 — optional semantic normalization (only after T01–T03 evaluation)
If context alone doesn't solve fragmentation, extend normalization to group contiguous cues into readable clauses. Ask Nemotron for ordered groups of existing IDs only, not timestamps or rewritten source. Validate exact ordered partition of all eligible IDs; no omissions, duplicates, reordering or merges across long silence/speaker boundary where known. Deterministically concatenate source, derive start from first and end from last raw cue; regenerate unique numeric IDs (preserve raw mapping); retain metadata and use existing translation engine. Limit duration/length using configurable conservative heuristics (initial proposed max 7s, no merge over >0.7s gap; tune using tests, not universal rules). Do not merge very long cues just to form full sentences. No internal split unless actual word/segment timestamps can be preserved reliably from source; current JSON3 parser drops segment offsets. Defer sub-cue alignment if not needed; no fabricated timing. If model output invalid, bounded retry then use unmerged cues. Verify player overlay displays grouped source and corresponding translation with seek, replay, pause, gap, adjacent cue boundaries; do not edit overlay unless a demonstrated issue requires it. Keep option to disable.
Example (synthetic): cues 101 "So if you look at the" [12,14], 102 "vision.md here." [14,16] -> one group [101,102], source concatenated, [12,16]. Existing translator produces one corresponding fa. Do not invent surrounding screenshot content.

### T05 — regression and evaluation
Run same fixtures and same captured 3–5 minute technical clip for A = original baseline, B = ID guard + deterministic cleanup, C = B + context, D = C + semantic merging if implemented. Same source track, target zh-TW, model/version, temperature and input snapshot; record commit, prompt version, outputs, model parameters, runtime, requests/tokens if reported, failures/retries. Include manual and auto track, video navigation, long lecture smoke test, other provider/manual import regression, popup progress and original text toggle. Compare blind if feasible. No fabricated measurement; mark unrun tests.
Fixed human rubric 0–5 each: semantic completeness, faithfulness (no inventions or shifted meaning), natural Taiwan Chinese, terminology consistency, timing/readability. 0 unusable; 1 severe errors; 2 frequent errors; 3 usable with noticeable issues; 4 minor issues; 5 no observed issues. Review identical timestamp regions and note concrete error examples. Proposed release gate: no regression in faithfulness/timing, improvement in fragmentation or naturalness on failing clip, 100% valid source mapping and target ID association for accepted batches, no invalid timestamps, no silently missing translation (existing partial status must be explicit), no secret leakage; compare cost/time and report rather than claim target achieved. For normalized text coverage account for justified deduplication via provenance. Test live NVIDIA only with user's configured key; mocked tests must run without secrets.

## 5. Compatibility, operational safeguards, and stopping conditions
Keep original manual import/export and original track selection. If grouping, auto path alone consumes normalized workfile; manual raw workfile remains available. Existing stored overlay cache is keyed by video ID; verify retranslation replaces the current video's result and never reuses stale enhanced results across model/language/track/mode. If adding context cache later, key by video/track, source hash, model, language, mode and prompt version; do not overhaul storage for MVP. Respect MV3 worker lifecycle; handle timeouts and popup close/navigation without claiming persistence not implemented. Keep API request count bounded and no infinite retry. Do not send credentials/transcript to additional services. Treat subtitles as data, not instructions. Preserve upstream license and attribution.
Stop after T03 if quality is sufficient; T04 is conditional, not mandatory. Stop and report if API incompatible, timestamp evidence insufficient, or required changes violate scope. Do not widen scope or silently introduce ASR/backend. Make fallback and limitations visible.
