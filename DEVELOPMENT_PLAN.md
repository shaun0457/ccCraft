# ccCraft — minimal caption preprocessing layer

Status: implementation pending. This revised plan supersedes the previous broader plan and tickets. Target: existing Chrome extension + NVIDIA Nemotron 3 Ultra (nvidia/nemotron-3-ultra-550b-a55b).

## Goal / intent / scope
Goal: turn fragmented YouTube automatic captions into coherent, readable source-language subtitle segments before translation, so the resulting Taiwan Traditional Chinese subtitles are natural and semantically faithful.
Intent: improve the input to ccCraft, not ccCraft's translation engine. The user already verified the existing Nemotron translation workflow basically works. The observed English fragment "vision.md here. And if you're going to" with unrelated Chinese illustrates the problem, but does not prove its cause.
Scope: ONE preprocessing layer between existing caption extraction and existing translation batching. It cleans raw text, uses global transcript context, restores punctuation, reconstructs sentence/clause boundaries, conservatively corrects obvious context-supported recognition errors, and returns a compatible workfile with deterministic timing. Semantic reconstruction is required, not an optional future feature.
Non-goals: rewriting translation prompts or batching, translation response parsing, retry, cache, overlay, player, UI redesign, new provider framework, ASR/audio download, backend, GPU deployment, agents, broad refactoring. Do not fix unrelated existing bugs in this task. Preserve manual import/export, other providers and upstream attribution.

## Design
Raw workfile -> preprocessWorkfile(rawWorkfile, selectedProviderConfig) -> existing translateWorkfile downstream -> existing overlay.
One small module (suggested src/caption-preprocessing.js, compatible with manifest/service-worker loading). Minimal call-site and module-loading changes. No new runtime dependency. Enable for automatic tracks on selected Nemotron model; manual tracks and other providers bypass by default. Provide a simple opt-out (configuration flag is sufficient; no new UI required).

Inside preprocessWorkfile:
1. Snapshot original workfile without mutation. Normalize whitespace, remove rolling duplicates only when exact overlap and timing evidence support it. Preserve legitimate repetitions, numbers, filenames, identifiers, speaker tags and negation.
2. Global Context Analysis: read full normalized transcript when within verified request budget; produce a compact source-language context profile (topic, terminology, proper nouns and likely ASR confusions). Use this only inside reconstruction; no changes to downstream translation prompt needed. For long transcripts, bounded windows/summaries with explicit fallback, never silent truncation.
3. Semantic Reconstruction: Nemotron proposes punctuation, complete readable clauses and grouping of contiguous raw cues, with conservative recognition correction. Use bounded chunks with read-only neighboring context and shared global profile. Prefer two logical operations (context then reconstruction), not extra agents. Ask for structured JSON with ordered groups, source IDs or source token spans, reconstructed source text, and explicit correction records (original, replacement, reason). No timestamps or translations generated by this model stage. Treat transcript as untrusted data, not instructions. Do not invent missing words or paraphrase; uncertain recognition remains unchanged. Corrections must preserve meaning; reject unsupported edits or excessive changes. Without audio cannot guarantee what was actually spoken.
4. Deterministic alignment and validation: validate complete ordered coverage of source cues/spans, no duplicates, dropped content or invented IDs. For merges use first raw start and last raw end; regenerate unique numeric cue IDs and formatted timestamps with same convention as existing code. If a cue contains the end of one sentence and beginning of another, split only when reliable original segment/word timing is available. Inspect JSON3 offsets and preserve them via a small parser change if necessary; otherwise retain whole-cue boundary or merge conservatively; never fabricate precise timestamps. Keep readable duration/length; initial heuristics max ~7 seconds, no merge over >0.7 seconds gap, tune with real fixtures. Preserve silence and known speaker boundaries. Reject invalid/overlapping intervals. Preserve raw mapping and correction log internally for review.
5. Return cloned existing workfile schema with video/source_track metadata and cues {id,start,end,start_time,end_time,source,fa:""}. Keep any provenance separately or as compatible additive metadata if verified safe. No change to downstream contract. If preprocessing fails or output invalid, bounded retry then fallback to original workfile with visible warning; no partial corruption. Do not log keys, signed URLs or private transcripts.

## Acceptance criteria / stop conditions
- Demonstrate fewer awkward mid-clause breaks and improved meaning on a real 3–5 minute auto-caption technical clip where available; show concrete before/after examples. Rate readability, semantic faithfulness, terminology and synchronization 0–5 using same clip; no regression in faithfulness or synchronization. Record runtime/request count, no invented measurements.
- All accepted reconstructed segments trace to original source; no unexplained dropped text, duplicates, reordered meaning or fabricated content. All timings finite, positive duration, ordered and non-overlapping; output is compatible with existing workfile and overlay.
- Tests cover split sentence across cues, two sentences within cue, rolling duplicates, legitimate repetitions, technical identifiers, long pause, ambiguous ASR, malformed/missing/duplicate model IDs, timeout, manual track bypass, disabled mode, immutable input.
- Existing translation/retry/storage/rendering behavior and manual import/export unchanged. Test fallback with no live key; live NVIDIA test only with configured user key. Explicitly mark unrun browser/live tests.
- Stop after a working preprocessing layer and evidence of improvement. If unrelated downstream bug blocks acceptance, report evidence separately and ask for scope approval; do not silently fix it.
